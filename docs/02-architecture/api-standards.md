# API Design Standards

> [Docs index](../README.md) › [02-architecture](README.md)

- **REST + JSON**, resource-oriented, `/api/v1/...`; OpenAPI 3.1 generated from code; TypeScript client generated (no hand-written fetch code).
- **Errors:** RFC 9457 Problem Details with stable `type` URIs and localisable `code`.
- **Idempotency:** `Idempotency-Key` header required on all POSTs that create facts.
- **Pagination:** cursor-based (`?cursor=&limit=`), max 200.
- **Filtering/sorting:** whitelisted fields only.
- **Concurrency:** `ETag` / `If-Match` on mutable master data.
- **Versioning:** URL major version; additive changes only within a version; deprecation headers + 6-month sunset.
- **Units in API:** quantities always as `{ "value": 18.562, "unit": "m3", "state": "loose" }`, never as bare numbers. Units are `m3` (`state` `bank` / `loose` / `compacted`, required), `t`, `kg`, `st`, `l`, `km`, `h`, `day` and `pcs` (`state` null). The value is a decimal JSON number at full precision; round only for display ([ADR-0025](../adr/0025-units-engine-and-materials.md)).
- **Time:** ISO 8601 with offset; server stores UTC.
- **Security:** OAuth 2.1 bearer tokens; scopes per client type; rate limits per tenant & user; request size limits; audit log for all admin endpoints.

## Implemented conventions (P1.3, `Karry.BuildingBlocks/Api`, `…/Idempotency`)

**Error responses** (`application/problem+json`, RFC 9457). Every error has `type` = `https://karry.app/problems/{code}`, `title`, `status`, a stable machine `code` and a `traceId` for support; validation errors add `errors` (field → messages).

| `Error` kind | HTTP | Example code |
|---|---|---|
| Validation | 400 | `request.invalid` (with `errors`) |
| Forbidden | 403 | `asset.forbidden` |
| NotFound | 404 | `asset.not_found` |
| Conflict | 409 | `asset.duplicate_code`, `idempotency.request_in_progress` |
| BusinessRule | 422 | `meter.backwards`, `idempotency.key_reused` |
| (unhandled exception) | 500 | `server.unexpected_error`: generic title, **no exception type, message or stack trace**; details only in logs with the trace ID (TC-P1-PLT-021) |

**Authentication and tenant (P1.5).** Module endpoints (`/api/v1/{module}/…`) require a bearer token and a tenant **by default**. The tenant comes only from the validated token's `tenant_id` claim (exactly one UUID), never from a header, path or body. No or invalid token → **401**; a valid token without exactly one tenant → **403 `tenant.missing`**. Both are answered before the endpoint runs. An endpoint opts out explicitly with `.AllowAnonymous()` (public) and/or `.AllowWithoutTenant()` (platform operator, branding lookup), and the opt-out is reviewed.

**Tenant address (P1.5).** When `Tenancy:BaseDomain` is set (e.g. `karry.app`), a request on `https://<slug>.karry.app` must carry a token of *that* tenant, otherwise **403 `tenant.host_mismatch`** (also for an unknown slug). Platform addresses (`api`, `www` and the other reserved names, multi-label hosts) are not tenant addresses and are not checked.

**Authorization (P1.9, [ADR-0022](../adr/0022-authorization-engine.md)).** Every tenant endpoint declares a permission (`module.resource.action`) or is a reviewed "any member" endpoint; an undeclared endpoint answers 403 `auth.permission_undeclared`. A caller without the permission gets 403 `auth.forbidden` (extension `permission`). An object outside the caller's scope (sites, warehouses) answers **404**, like a missing one. A privileged change without a sign-in of the last 5 minutes gets 401 `auth.step_up_required` (extension `maxAge`) with `WWW-Authenticate: Bearer error="insufficient_user_authentication", max_age=300` (RFC 9470), whether the endpoint always needs it or the handler decides from the change; the client re-authenticates and retries. An endpoint addressing a resource by route checks that the resource exists in the caller's company **before** validating the body, so another tenant's ID or code answers 404, never 400.

**Sensitive fields (P1.9, US-P1-IAM-07).** A property marked `[Sensitive("module.resource.field")]` is written only when the caller may read it on the object's site (`ISiteScoped`; an object without a site uses only tenant-wide roles). **Masked**: the property is absent and its JSON name is listed in the object's `maskedFields` array (the UI shows `•••` with "hidden by policy"). **Hidden**: absent and not listed. The value never appears in any form. The contract marks such properties with `x-karry-sensitive` and never lists them as required. Setting a sensitive field without the Write level is 403 `auth.field_not_writable` (extension `field`); writable sensitive inputs are nullable (null = not set). Exports and PDFs use `SensitiveExport` (hidden columns left out, unreadable cells `•••`).

**Site tablets (P1.15, [ADR-0028](../adr/0028-field-devices-offline-data-shared-tablet.md)).** Under `/api/v1/identity/devices`: `POST /enrollments` (`identity.devices.manage` on the site; body `{siteId}`; 201 with `enrollmentId`, `siteId`, `code` (shown only here, `XXXX-XXXX-XXXX-XXXX`), `url` (`https://<company>.<field address>/enroll#<code>`, the code in the fragment) and `expiresAt` (15 minutes); 400 `devices.site_invalid`, 403 `identity.scope_exceeded`); `GET /devices` (`identity.devices.manage`; the tablets of the caller's sites, newest first: name, model, platform, app version, site, status `active` / `revoked`, enrolled, last seen, revoked); `POST /{id}/revoke` (`identity.devices.manage`; 404 `devices.not_found` outside the caller's sites, 409 `devices.already_revoked`); `POST /enroll` (anonymous, no tenant: body `{tenant (slug), code, publicKey (JWK P-256), proof, name, model, platform, appVersion}`, `proof` = P1363 signature over `karry-enroll:<code>`; 201 with `deviceId`, `tenantId`, `siteId`, `pinKey` (base64, only here), `settings` (`autoLockMinutes`, `offlineSessionHours`) and `serverTime`; 404 `devices.enrollment_unknown`, 422 `devices.enrollment_expired` (expired or used), 400 `devices.key_invalid` (the code stays usable)). **Device endpoints** take `Authorization: Device <compact JWS ES256>` (header `{alg, typ: karry-device+jwt, kid: deviceId}`, payload `{tid, iat, exp (≤ 5 min after iat), jti, htm, htu (path)}`) and refuse a person's token; failures are 401 `devices.assertion_invalid`, `devices.assertion_replayed`, `devices.clock_skew` (with `serverTime`; a minute of leeway) and `devices.revoked`: `GET /me` (the tablet's own record, status, settings, server time) and `POST /unlock` (`{employeeId, pin}`: an active field user with a role on the tablet's site or company-wide; 200 `{userId, name, serverTime}`; 401 `identity.unlock_refused`, `identity.pin_wrong`, `identity.pin_locked` (5 wrong PINs lock 15 minutes, ledger event `identity.user_pin_locked`)). A person's token never reaches a device endpoint and a device never reaches a person's endpoint.

**Identity endpoints (P1.8, permissions P1.9).** Under `/api/v1/identity`: `POST /invitations` (`identity.users.manage`, `Idempotency-Key`; 201 with `userId`, `invitationId`, `expiresAt`, `delivered`; 409 `identity.user_exists` / `identity.account_exists`); `POST /invitations/accept` (anonymous: the token is the credential and names the tenant; 204, 404 `identity.invitation_invalid` for any unknown token, 409 `identity.invitation_used`, 422 `identity.invitation_expired`, 400 `identity.password_rejected` from Keycloak's policy); `POST /field-users` (`identity.users.manage`; employee ID + PIN; the PIN is never returned); `POST /users/{id}/deactivate` (`identity.users.manage`; idempotent, 422 `identity.cannot_deactivate_self`); `PUT /users/{id}/roles` (`identity.users.manage`; full replacement of the assignments, default or custom roles; 422 `identity.cannot_change_own_roles` and `identity.user_deactivated`, 400 `identity.role_needs_account` for an office role on a field user; giving or taking a privileged role or permission needs step-up; Keycloak's `mfa-required` follows the roles and the sessions end when a second factor becomes required; repeating the request repairs a Keycloak failure); `POST /users/{id}/invitation` (`identity.users.manage`, `Idempotency-Key`; a new link, the previous one answers like an unknown link; 422 `identity.not_invited`); `PUT /users/{id}/pin` (`identity.users.manage`, P1.14; body `{pin}`: sets or replaces a field user's PIN, which is hashed at once and never returned or ledgered (`identity.user_pin_set`); 204; 400 `identity.pin_invalid` / `identity.pin_too_simple`; 422 `identity.not_field_user`, `identity.user_deactivated`; 404 outside the caller's sites); `GET /users` (`identity.users.read`; cursor pagination on the UUIDv7 key, filtered by the caller's sites); `GET /users/{id}` (`identity.users.read`; 404 outside the caller's sites; a user has `pinSet`: whether a field user has a PIN); `GET /me` (any member); `GET /me/access` (any member; the caller's granted permission codes, so the apps show only what the person may use: navigation only, the server still decides). Roles (P1.9): `GET /permissions` (the catalogue: permissions with module, scope and privileged flag; sensitive fields with their fallback), `GET /roles`, `GET /roles/{code}` (all `identity.roles.read`; a role has `code`, `isDefault`, `name` and `description` for custom roles (the apps translate default codes), `basedOn`, `office`, `privileged`, `permissions` and the effective `fieldLevels` of every declared field as `hidden` / `masked` / `read` / `write`); `POST /roles` (`Idempotency-Key`; from scratch or a clone with `basedOn`, whose content fills what is left out; 201), `PUT /roles/{code}` (custom roles: full replacement; 422 `identity.default_role_readonly` for a default role), `PUT /roles/{code}/field-levels` (any role: full replacement, a field left out goes back to its default), `DELETE /roles/{code}` (204; 422 `identity.default_role_undeletable`, 409 `identity.role_in_use`), all `identity.roles.manage`. Errors: 400 `identity.permission_unknown`, `identity.field_unknown`, `identity.field_level_invalid`, `identity.role_unknown`, `identity.role_name_invalid`; 403 `identity.escalation` (a privileged permission the caller lacks tenant-wide); 404 `identity.role_not_found`; 409 `identity.role_exists` (same name). A token of a deactivated user gets 401 `auth.revoked` on every tenant endpoint. Giving roles is refused with 403 `identity.scope_exceeded` (outside the caller's sites) or `identity.escalation` (rights the caller lacks). `POST /api/v1/tenancy/tenants` accepts an optional `admin` (first Tenant Admin, invited by e-mail) and reports `adminInvitation`.

**Billing endpoints (P1.10, [ADR-0023](../adr/0023-plans-subscriptions-entitlements.md)).** Under `/api/v1/billing`, platform operators only (no tenant in the token; a tenant token gets 403): `GET /plans` (the newest version of each plan), `GET /plans/{code}` (every version, newest first; 404 `billing.plan_not_found`), `POST /plans` (`Idempotency-Key`; publishes the next version of a plan, or version 1 of a new one, with its full content: `features`, `limits` (a limit left out is unlimited) and `prices` (`currency`, `period` `monthly` / `annual`, `perSite`, `extraAsset`); 201; existing subscriptions keep their version). Errors: 400 `billing.plan_code_invalid`, `billing.plan_name_invalid`, `billing.feature_unknown`, `billing.limit_unknown`, `billing.limit_invalid`, `billing.currency_unsupported`, `billing.price_invalid`, `billing.price_duplicate`; 409 `billing.plan_version_conflict` (another operator published at the same time). Subscriptions (P1.10), platform operators only, run in the addressed tenant's unit of work (its ledger): `GET /tenants/{tenantId}/subscription`; `PUT /tenants/{tenantId}/subscription` (`planCode`, optional `planVersion` (newest by default), `period`, `sites`, `extraAssets`, `addOns`, `extraFeatures`, `limitOverrides`; 400 `billing.plan_unknown`, `billing.add_on_invalid`, `billing.quantity_invalid`; 422 `billing.subscription_closed`); `POST /tenants/{tenantId}/subscription/actions` (`Idempotency-Key`; `action` = `activate` / `missed-payment` / `payment` / `cancel`; 422 `billing.transition_invalid`, `billing.reactivation_window_passed`); `GET /tenants/{tenantId}/invoices`; `POST /tenants/{tenantId}/invoices` (`Idempotency-Key`; `number`, `amount` (decimal, negative for a credit note), `currency`, `issuedOn`, `dueOn`; 409 `billing.invoice_number_taken`); `POST /tenants/{tenantId}/invoices/{invoiceId}/payment` (`Idempotency-Key`; `paidOn`; a PastDue, Restricted or Suspended subscription becomes Active in the same change; 409 `billing.invoice_already_paid`); an unknown tenant is 404 `billing.tenant_not_found`. A subscription has `status` (`trial`, `active`, `past_due`, `restricted`, `suspended`, `cancelled`, `expired`, `deleted`), `statusSince`, `trialEndsAt`, `unpaidSince` and its terms. The company itself reads `GET /subscription` and `GET /invoices` (`billing.subscription.read`). Entitlements (P1.10): `GET /entitlements` (any member of the company) returns `planCode`, `planVersion`, `status`, `trialEndsAt`, `features` and `limits` (tenant-wide totals; a limit left out is unlimited); it only drives what the apps show. Usage (P1.10): `GET /usage` (`billing.subscription.read`) returns `items` (`metric`, `usage` (live count), `limit` and `ceiling` (tenant-wide; null when unlimited), `state` `within` / `over` / `blocked`) and `snapshotOn` (the last daily snapshot). Creating a counted item at the ceiling (the limit plus a 10 % grace, at least one) answers **403** `billing.limit_reached` with members `metric`, `limit` and `usage`; field capture never does. Office invitations (`POST /api/v1/identity/invitations`) check the `office-users` seat limit this way. Subscription state (P1.10): on tenant endpoints, a state that does not allow the work answers **403** `billing.subscription_restricted` (office writes while Restricted; field capture, billing and export continue), `billing.subscription_suspended` (every write but billing and export) or `billing.subscription_inactive` (Cancelled, Expired, Deleted: only billing, export and reading one's own account), with member `subscriptionStatus`; platform-operator and anonymous endpoints are not subject to it. An endpoint declared `.RequiresFeature("<code>")` answers **403** `billing.feature_not_in_plan` (extension `feature`, no data) when the plan does not include the feature, checked after the permission.

**Organization endpoints (P1.11, [ADR-0024](../adr/0024-sites-geometry-and-shift-time.md)).** Under `/api/v1/organization`. Sites: `GET /sites` (`organization.sites.read`; the sites in the caller's scope, by code; `?includeArchived=true` adds archived ones) and `GET /sites/{siteId}` (404 `organization.site_not_found` outside the scope); `organization.sites.manage`: `POST /sites` (`Idempotency-Key`; 201), `PUT /sites/{siteId}` (the same body; repeating it changes nothing), `POST /sites/{siteId}/archive`, `POST /sites/{siteId}/restore`. A site has `code` (2–20 letters, digits, dashes; upper-cased; unique in the company for ever, never changed: 409 `organization.site_code_taken`, 400 `organization.site_code_fixed`), `name`, `type` (`quarry`, `sand-washing`, `mine`, `warehouse-only`, `workshop`), `address` (`line`, `city`, `region`, `postalCode`, `country` ISO 3166-1 alpha-2), `location` (`latitude`, `longitude`, WGS 84), `boundary` (a GeoJSON Polygon, `[longitude, latitude]`, or null), `timeZone` (IANA), `currency` (override or null), `status` `active` / `archived`, `createdAt`, `changedAt`, `archivedAt`. Errors: 400 `organization.site_code_invalid`, `site_name_invalid`, `site_type_invalid`, `site_address_invalid`, `site_location_invalid`, `boundary_invalid` (one ring of 4–500 points), `boundary_not_closed`, `boundary_self_intersecting`, `boundary_too_large` (over 200 km²), `time_zone_unknown`, `currency_unsupported`. Creating or restoring a site beyond the sites bought plus the grace answers 403 `billing.limit_reached` (`metric` `sites`). **Shifts** (US-P1-ORG-02; reads with `organization.sites.read`, changes with `organization.shifts.manage` on the site, else 403 `organization.site_not_managed`; an archived site answers 409 `organization.site_archived`): `GET /sites/{siteId}/shift-patterns` (versions by `effectiveFrom`), `PUT /sites/{siteId}/shift-patterns/{effectiveFrom}` (body `shifts`: 1–12 of `code` (1–16 letters, digits, dashes), `name`, `start` and `end` as `HH:mm` on the site's clock (an end not after the start is the next day; equal is 24 h), `days` `mon`..`sun`; a version not yet in effect is replaced) and `DELETE` of a future version (204); `GET /sites/{siteId}/non-working-days?from&to` (default: a year from the site's today), `PUT /sites/{siteId}/non-working-days/{date}` (`kind` `public-holiday` / `closure` / `other`, `name`) and `DELETE` (204); `GET /sites/{siteId}/shift-instances?from&to` (computed, not stored; default the next 30 days; at most 366 days) answers `date` (the local date the shift starts on), `code`, `name`, `startsAt`, `endsAt` (UTC), `timeZone`, `lengthMinutes` (11 or 13 h for a 12 h night shift around clock changes). Only dates after the site's today change a pattern (any date for the site's first one), non-working days from today: 400 `organization.date_in_past` (with `today`). Errors: 400 `organization.shifts_invalid`, `shift_code_invalid`, `shift_code_duplicate`, `shift_name_invalid`, `shift_time_invalid`, `shift_days_invalid`, `shifts_overlap` (`shifts` names the two codes), `day_kind_invalid`, `day_name_invalid`, `range_invalid`; 404 `organization.shift_pattern_not_found`, `non_working_day_not_found`. Each change is in the company's ledger and updates the stored instances of the next 30 days in the same transaction.

**Materials endpoints (P1.12, [ADR-0025](../adr/0025-units-engine-and-materials.md)).** Under `/api/v1/materials`.
- **Reading** (`materials.catalog.read`, every default role): `GET` lists the company's materials by code (`?includeArchived=true` adds archived ones). `GET /{materialId}` returns one, or 404 `materials.material_not_found`. A material has `code`, `name`, `kind` (`raw-rock` / `product`), `status` and `densities`. `densities` holds its versions, oldest first: `effectiveFrom`, `bank` / `loose` / `compacted` in t/m³ (null when the material has no such state), `moisture` (mass fraction) and `swell` (bank / loose − 1, or null).
- **Changing** (`materials.catalog.manage`, Tenant Admin, privileged):
  - `POST` (`Idempotency-Key`): `code`, `name`, `kind`, the first `densities` and an optional `effectiveFrom` (any date; default the company's today). Answers 201, or 409 `materials.material_code_taken`.
  - `PUT /{materialId}`: `name` and `kind`; the code never changes.
  - `POST /{materialId}/archive` and `/restore`.
  - `PUT /{materialId}/densities/{effectiveFrom}`: densities from that date, which must be after the company's today (400 `materials.date_in_past` with `today`). A version not yet in effect is replaced. 409 `materials.material_archived`.
  - `DELETE /{materialId}/densities/{effectiveFrom}`: a future version only. 404 `materials.density_version_not_found`; 422 `materials.last_density_version`.
- **Validation errors** (400): `materials.code_invalid`, `materials.name_invalid`, `materials.kind_invalid`, `materials.density_required`, `materials.density_invalid` (with `state`; 1.2–3.2 t/m³, at most 4 decimals), `materials.moisture_invalid` (0–0.25), `materials.swell_invalid` (with `swell`; must be 0.10–0.80).
- **Conversion** (`materials.catalog.read`, no idempotency key since nothing is stored): `POST /{materialId}/conversions` takes `quantity` (`{value, unit, state}`), the target `unit` and `state`, an optional `on` (default the company's today) and an optional measured `moisture`. It answers `result`, the `factors` used (`density.<state>` in t/m3, `moisture`, `swell`) and `densitiesFrom`, the date of the version used. An archived material still converts. Errors (400): `units.quantity_invalid`, `units.not_convertible`, `units.density_missing` (with `state`), `materials.no_density_version` (with `on`), `materials.moisture_invalid`.
- Every change is in the company's ledger: `materials.material_created.v1`, `material_changed`, `material_archived`, `material_restored`, `density_version_set` (with before and after) and `density_version_removed`.

**Assets endpoints (P1.13, [ADR-0026](../adr/0026-asset-registry-meters-and-labels.md)).** Under `/api/v1/assets`. Site-scoped: a site role reaches only the assets on its sites, and an asset elsewhere answers 404 `assets.asset_not_found`.
- **Reading** (`assets.registry.read`, every default role):
  - `GET /types`: the type catalogue (`code`, `defaultMeters` `hours` / `km`, `components`); the apps translate the codes.
  - `GET`: the register by code. `q` matches a fragment of the code, name, make, model, serial or plate; filters `siteId`, `type`, `status` (disposed assets only with `status=disposed`). Cursor paging: `limit` (default 50, at most 200) and `cursor` (the `nextCursor` of the previous page, null on the last one). 400 `assets.limit_invalid`, `assets.type_invalid`, `assets.status_invalid`.
  - `GET /{assetId}`. An asset has `code`, `name`, `type`, `make`, `model`, `serialNumber`, `plate`, `year`, `acquiredOn`, `siteId`, `status` (`active`, `in-repair`, `idle`, `disposed`), `sites` (its arrivals at sites, oldest first: `siteId`, `from`) and `disposedAt`.
- **Changing** (`assets.registry.manage`: Tenant Admin, Site Manager, Maintenance Planner, on their sites):
  - `POST` (`Idempotency-Key`): the details and `siteId` (an active site the caller manages, else 400 `assets.site_invalid`). `meters` lists its meters (`kind`, `initialReading`, `installedOn`); left out, the asset gets its type's default meters from 0, installed on the acquisition date (else today); `[]` gives none. Answers 201, 409 `assets.asset_code_taken`, or 403 `billing.limit_reached` (assets not disposed, soft limit).
  - `PUT /{assetId}`: the details; the code never changes. 409 `assets.asset_disposed`.
  - `POST /{assetId}/move` (`siteId`): the caller manages both sites. Moving to the current site changes nothing.
  - `POST /{assetId}/status` (`status`). Bringing a disposed asset back follows the asset limit.
  - 403 `assets.site_forbidden` when the caller sees the asset but does not manage its site.
- **Validation errors** (400): `assets.code_invalid`, `assets.name_invalid`, `assets.type_invalid`, `assets.text_too_long` (with `field`, `max`), `assets.year_invalid` (1950 to next year), `assets.acquired_on_invalid` (1950-01-01 to the company's today).
- **QR labels** (US-P1-AST-02 AC2, TC-P1-AST-001). An asset's `label` is `KRY1:` and a random 26-character base32 token, not derived from its ID.
  - `GET /labels/{label}` (read): the asset the label points at, with or without the prefix, any case. A label of another company, of an asset outside the caller's sites, or a reissued one answers 404 `assets.label_unknown`.
  - `POST /{assetId}/label` (manage): a new token; the old label stops resolving (`assets.asset_label_reissued.v1`, without the token). 409 `assets.asset_disposed`.
  - `POST /labels/sheet` (manage): `assetIds` (1 to 240, in print order) and `skip` (0 to 23 labels already used on the first sheet) give `application/pdf`: A4 sheets of 3 × 8 labels of 70 × 37 mm, each with the QR code, code, name and plate (else serial). 400 `assets.label_sheet_invalid`; 404 for an asset out of reach.
- **Photo** (US-P1-AST-01 AC3): one current photo per asset, in object storage under `tenants/{tenant}/assets/{asset}/photo-{sha256}`. An asset's `photo` is `null` or `sha256`, `contentType`, `bytes`.
  - `PUT /{assetId}/photo` (manage, `Idempotency-Key`): the raw image as the body, with an `image/jpeg`, `image/png` or `image/webp` content type (else 415). The type stored is the one read from the content; at most 5 MB. 400 `assets.photo_type_unsupported`, `assets.photo_too_large`; 409 `assets.asset_disposed`; 422 `assets.photos_unavailable` when the environment has no object storage. The same photo again changes nothing; a new one replaces the old object.
  - `GET /{assetId}/photo` (read): the image, with `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`, `Cache-Control: private` and the SHA-256 as `ETag`. 404 `assets.photo_not_found`.
  - `DELETE /{assetId}/photo` (manage). Each change is in the ledger (`assets.asset_photo_changed.v1`, with the hash, not the image).
- **Meters** (US-P1-AST-03). There is no route to change or remove a reading (TC-P1-AST-002).
  - `GET /{assetId}/meters` (read): `kind` (`hours` / `km`), `unit` (`h` / `km`), `initialReading`, `installedOn`, `status` (`ok`, `failed`, `replaced`), `offset` (0 until meter replacement, Phase 2), `lastValue`, `lastReadAt`.
  - `POST /{assetId}/meters` (manage, `Idempotency-Key`): `kind`, `initialReading` (default 0), `installedOn` (default today). The initial reading opens the history, read at 00:00 UTC on the installation date.
  - `POST /{assetId}/meters/{meterId}/readings` (manage, `Idempotency-Key`): `value` and `readAt` (default now). 400 `assets.reading_invalid` (0 to 9,999,999.9, one decimal), `assets.reading_decreased` (with `lastValue`), `assets.reading_before_last` (with `lastReadAt`), `assets.reading_in_future` (5 minutes of clock tolerance); 409 `assets.meter_not_counting` (failed meter), `assets.meter_changed` (another reading was saved meanwhile; retry).
  - `POST /{assetId}/meters/{meterId}/status` (manage): `ok` or `failed`; 422 `assets.meter_replacement_unavailable` for `replaced`.
  - `GET /{assetId}/meters/{meterId}/readings` (read): newest first, cursor paging (`cursor` is a reading ID). 404 `assets.meter_not_found` for a meter of another asset.
  - A disposed asset takes no new meter or reading (409 `assets.asset_disposed`); its history stays readable. Errors (400): `assets.meter_kind_invalid`, `assets.installed_on_invalid`, `assets.meter_status_invalid`.
- Every change is in the company's ledger: `assets.asset_registered.v1`, `asset_changed` (with before and after), `asset_moved`, `asset_status_changed`, `asset_label_reissued`, `meter_added`, `meter_reading_recorded` and `meter_status_changed`. The site history (`assets.site_assignments`) and the readings (`assets.meter_readings`) are append-only (trigger, and no `UPDATE`/`DELETE` grant).

**Imports endpoints (P1.14, [ADR-0027](../adr/0027-excel-import.md)).** Under `/api/v1/imports`, for `imports.files.manage` (Tenant Admin); each kind also needs the permission of the data it writes (403 `imports.kind_forbidden`).
- `GET /templates/{kind}?language=fr|en` (default `fr`): the kind's `.xlsx` template. The first sheet takes the data (headers in the chosen language, required ones marked `*`, text columns formatted as text, drop-downs from the company's lists); then the instructions and the hidden lists. Every value we write is protected against formula injection. 404 `imports.kind_unknown`, 400 `imports.language_unsupported`.
- `POST ?kind=&fileName=` (`Idempotency-Key`; the body is the `.xlsx`, content type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`): checks the file (`.xlsx` only, recognised by content, at most 10 MB; macros, ActiveX, embedded objects and external links are refused), keeps it and answers 202 with the job, `validating`. Only the file's name is kept, not its path. 404 `imports.kind_unknown`, 403 `imports.kind_forbidden`, 400 `imports.file_missing`, `imports.file_type_unsupported`, `imports.file_too_large`, `imports.file_active_content`, `imports.file_too_many_rows`, `imports.file_unreadable`, `imports.file_name_invalid`; 422 `imports.storage_unavailable` without a bucket.
- The worker then validates the file with the uploader's current rights. A job is `id`, `kind`, `fileName`, `size`, `sha256`, `status`, `rows`, `errors`, `warnings`, `created`, `updated`, `unchanged`, `scanner`, `uploadedAt`, `changedAt` and `fileKept` (false once the file was deleted after 90 days). It goes `validating` → `validated` → `committing` → `committed`, or `discarded`; poll it while it is `validating` or `committing`. A commit that finds an error writes nothing and returns it to `validated` with the new counts.
- `GET` (newest first), `GET /{importId}`, `GET /{importId}/issues?severity=error|warning` and `GET /{importId}/rows` (the preview: `row`, `key`, `action` `create` / `update` / `unchanged`): cursor paging (`limit` 1 to 200, default 50; `cursor` is the `nextCursor` of the previous page). 400 `imports.limit_invalid`, `imports.cursor_invalid`, `imports.severity_invalid`; 404 `imports.job_not_found` (also for another company's import).
- An issue is `row` (0 for the file itself, 1 for the headers), `column` (the template's key), `cell` (`C14`), `code`, `severity` and `args`. Codes so far: `imports.column_unknown` (warning), `imports.column_duplicate`, `imports.column_missing`, `imports.cell_error` (errors), `imports.formula_value_used` (warning: the saved value is used, the formula never runs); on row 0, `imports.kind_forbidden` (rights removed since), `imports.file_deleted`, `imports.file_infected` and the file errors above. Shared row codes: `imports.value_required`, `imports.number_invalid`, `imports.date_invalid` (`yyyy-mm-dd` or an Excel date), `imports.key_duplicate` (on every row with that key; `args` `key`, `rows`); on row 0, `imports.data_changed` (the commit could not save because the data changed meanwhile; validate again) and `billing.limit_reached` (the creations would pass the plan's limit). Each kind adds the codes of its own rules.
- Kinds (P1.14 slices 3–5; key in brackets, `*` = required). Onboarding order: sites, then materials, assets and users, then meters.
  - `sites` (`organization.sites.manage`) [code]: `code*`, `name*`, `type*` (drop-down), `address*`, `city*`, `region`, `postalCode`, `country*` (ISO, e.g. `TN`), `latitude*`, `longitude*`, `timeZone` (IANA; empty = the company's), `currency` (drop-down; empty = the company's). A new code creates the site; a known one changes its details and keeps its boundary (drawn on the map, not in the template); a change of clock moves its future shift instances. Codes: those of the API (`organization.site_code_invalid`, `site_name_invalid`, `site_type_invalid`, `site_address_invalid` on the address, `site_location_invalid` on the latitude, `time_zone_unknown`, `currency_unsupported`), and `organization.site_archived` (restore it on screen first). The `sites` limit counts the file's creations.
  - `materials` (`materials.catalog.manage`) [code]: `code*`, `name*`, `kind*` (`raw-rock`, `product`), `bank`, `loose`, `compacted` (t/m³), `moisture` (fraction), `effectiveFrom` (default the company's today). A new code is created with these densities. A known code changes its name and kind; densities that differ from those in force on `effectiveFrom` become a new version, which must start after today (else `materials.date_in_past` on `effectiveFrom`: past quantities keep theirs); empty densities leave its versions alone. Codes: those of the API (`materials.code_invalid`, `name_invalid`, `kind_invalid`, `density_required`, `density_invalid` on the density's column, `moisture_invalid`, `swell_invalid` on `loose`, `material_archived`).
  - `assets` (`assets.registry.manage`) [code]: `code*`, `name*`, `type*`, `site*` (the site's code; drop-down of the active sites the user manages), `make`, `model`, `serialNumber`, `plate`, `year`, `acquiredOn`. A new code is registered with its type's default meters (reading 0 on `acquiredOn`, or today); an existing one is updated (name, type, details) or moved to the new site (site history kept). Row codes are those of the API: `assets.code_invalid`, `assets.type_invalid`, `assets.site_invalid`, `assets.site_forbidden`, `assets.asset_disposed`, and the detail errors on their column (`assets.name_invalid`, `assets.text_too_long`, `assets.year_invalid`, `assets.acquired_on_invalid`). The `assets` limit counts the file's creations.
  - `users` (`identity.users.manage`) [e-mail, phone or employee ID]: `firstName*`, `lastName*`, `email` / `phone` (an office user, invited) or `employeeId` (a field user), `role*` (drop-down of the roles a file may give), `site` (drop-down of the active sites the user manages users on; empty = company-wide). One row per person with one role. A new office user is saved `invited` by the commit; the Identity outbox then creates the Keycloak account and sends a fresh invitation (the screen shows them invited until then; a Keycloak username that belongs to someone else is logged as event 2110 and the user stays invited). A new field user is active **without a PIN** (a file never carries PINs): an administrator sets it with `PUT /identity/users/{id}/pin`. A known user gets the row's role added when missing; nothing is removed and names are kept. **Privileged roles are refused** (`identity.role_privileged`): they are given on screen, with step-up. Codes: `identity.user_kind_ambiguous` (contact and employee ID on one row), `identity.contact_required`, `identity.email_invalid`, `identity.phone_invalid`, `identity.employee_id_invalid`, `identity.role_unknown`, `identity.role_needs_account` (an office role for a field user), `identity.site_invalid`, `identity.scope_exceeded`, `identity.escalation`, `identity.user_deactivated`, `identity.name_invalid`. The `office-users` limit counts the file's office users; field users are never limited.
  - `meters` (`assets.registry.manage`) [asset code / meter kind]: `asset*`, `meter*` (`hours`, `km`), `reading*`, `readOn` (default today). A machine without that meter gets it with this first reading; a meter gets a new reading when the value differs (same value → `unchanged`). Codes: `assets.asset_not_found` (also an unknown or unmanaged machine), `assets.meter_kind_invalid`, `assets.reading_invalid`, `assets.reading_decreased`, `assets.reading_before_last`, `assets.reading_in_future`.
- `POST /{importId}/commit` (the kind's permission too): 200 with the job, `committing`; the worker commits it with the requester's current rights. 409 `imports.job_not_validated`, 422 `imports.job_has_errors`. `POST /{importId}/discard`: 200, `discarded`; 409 `imports.job_not_discardable` once committed or committing.
- Ledger: `imports.import_uploaded.v1`, `import_validated` (with the scanner), `import_commit_requested`, `import_committed`, `import_discarded`, `import_file_deleted`.

**Feature flags endpoints (P1.10, [ADR-0019](../adr/0019-feature-flags.md)).** Under `/api/v1/flags`. `GET` (any member of the company, account access) returns `flags`, a map from flag key to the value evaluated for the caller (user → company → platform → environment → default); it only drives what the apps show. Platform operators only (no tenant in the token; a tenant token gets 403): `GET /catalog` (every declared flag with `key`, `description`, `default`, `environment` and `platform` values and `platformChangedAt`); `PUT /{key}` (`Idempotency-Key`; `enabled` `true` / `false` / `null` to clear; 400 `flags.subject_not_allowed` when a `userSubject` is given); `GET /tenants/{tenantId}` (the company's overrides: `key`, `userSubject` (null for the whole company), `enabled`, `changedAt`); `PUT /tenants/{tenantId}/{key}` (`Idempotency-Key`; `enabled`, optional `userSubject`; runs in the tenant's unit of work, so the change is in its ledger). Errors: 400 `flags.flag_unknown` (flags are declared in code), `flags.subject_invalid`; 404 `flags.tenant_not_found`.

**Tenancy endpoints (P1.5).** `POST /api/v1/tenancy/tenants` (platform operator, `Idempotency-Key` required; 201 created, **200 for the same slug and name again**, 409 `tenant.slug_taken`, 400 `tenant.slug_invalid` / `tenant.slug_reserved` / `tenant.name_invalid`); `GET /api/v1/tenancy/current` (the caller's company with its settings: `legalName`, `primaryColour`, `language`, `currency`, `unitSystem` `metric` / `imperial`, `timeZone`, `fiscalYearStartMonth`, `logoUrl`, `settingsChangedAt`); `GET /api/v1/tenancy/public/{slug}` (anonymous branding for the login page: `slug`, `name`, `primaryColour`, `logoUrl`; 404 `tenant.not_found`) and `GET /api/v1/tenancy/public/{slug}/logo` (the image, `nosniff`; 404 `tenant.logo_not_found`). **Company settings (P1.11, US-P1-TEN-04),** `tenancy.settings.manage`: `PUT /api/v1/tenancy/settings` (every field; repeating the same values changes nothing; 400 `tenant.legal_name_invalid`, `tenant.colour_invalid`, `tenant.colour_contrast` (below 4.5:1 against white; extension `minimumContrast`), `tenant.language_unsupported`, `tenant.currency_unsupported`, `tenant.unit_system_invalid`, `tenant.time_zone_unknown` (IANA names), `tenant.fiscal_month_invalid`); `PUT /api/v1/tenancy/settings/logo` (the image as the body; type read from the content, never from `Content-Type`; 400 `tenant.logo_type_unsupported`, `tenant.logo_too_large` (256 KB, extension `maxBytes`)); `DELETE /api/v1/tenancy/settings/logo`. All three return the company as `/current` does; each change is in the company's ledger (`tenancy.tenant_settings_changed.v1` with before and after, `tenancy.tenant_logo_changed.v1` with the fingerprint).

**Audit endpoints (P1.6).** `POST /api/v1/audit/verify` recomputes the caller's tenant ledger and returns `{valid, entriesChecked, firstBrokenSequence, problem, headHash, verifiedAt}`.

**Correlation (P1.4, `Karry.BuildingBlocks/Observability`).** Every response, success or error, carries `X-Correlation-Id` (the W3C trace ID, 32 hex characters) and `traceparent`. The problem `traceId` is the same value, so the ID a user quotes from an error dialog finds the trace directly. A caller that sends `traceparent` (portal, field app) joins the same trace (TC-P1-OPS-005).

Framework errors use the same shape: unknown route `route.not_found`, malformed JSON `request.invalid`, 405/415 likewise. Codes are part of the contract: never rename one; add a new code instead.

**Validation:** request bodies are validated by FluentValidation before the handler (`.Validate<TRequest>()`); every request type needs a validator.

**Idempotency** (`.RequireIdempotencyKey()`): header `Idempotency-Key` (1–200 printable characters). Same key + same request → the stored response is replayed with `Idempotency-Replayed: true` (also for 4xx); same key + different request → 422 `idempotency.key_reused`; while the first is running → 409 `idempotency.request_in_progress`; missing key → 400 `idempotency.key_required`; 5xx responses are not stored (the client may retry). Records are kept 24 h; a reservation abandoned by a crashed process is released after 2 min. Scope: tenant + user from P1.5/P1.8.

**OpenAPI:** `/openapi/v1.json` (generated from code) in every environment except production. The contract is also generated at **build time** into [`src/backend/Karry.Host/openapi/v1.json`](../../src/backend/Karry.Host/openapi/v1.json) and committed: `ci / backend` fails if it is stale, `ci / openapi-diff` (oasdiff) fails on a **breaking change** against the base branch, and `ci / tenant-isolation` attacks every operation in it. Every endpoint needs `.WithName(...)` (operationId) and declares its problem responses (`.ProducesProblem(...)`). The frontend's typed client (`@karry/api-client`, openapi-typescript + openapi-fetch) is generated from the same file; CI fails when it is stale. The client throws every non-2xx as `ApiError` (status, problem `code`, correlation ID), attaches the access token, and adds an `Idempotency-Key` to every write unless the caller sets one.
