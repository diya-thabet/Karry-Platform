# P2.11 shift report PDF and public verification: slice plan

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Sub-phases](sub-phases.md#p211--shift-report-pdf--public-verification) · [Tracker](tracker.md)

**In plain words:** a signed shift report anyone can print. Its QR code opens a public page that says whether the
document is genuine, and a PDF changed by one byte is shown as not genuine. Design: [ADR-0040](../../adr/0040-documents-and-public-verification.md).

## 1. Scope

| Story | ACs in P2.11 |
|---|---|
| US-P2-SIG-05 Signed shift report PDF | AC1 (per shift and site: entries with values, Δ, operator, controller, flags, signature images, verification QR), AC2 (document hash in the footer, QR to the verification page), AC3 (200 entries in < 10 s) |
| US-P2-SIG-06 Public verification page | AC1 (type, date, issuing company, status, hash; names only as the company's policy allows), AC2 (rate-limited, no enumeration) |

Tests: TC-P2-DOC-001 (200 entries < 10 s, the QR verifies), TC-P2-SIG-005 (enumeration: random IDs and tokens give
the same "not found" answer and timing; the rate limit hits), TC-P2-DOC-002 (a changed PDF byte → "not genuine"),
TC-P2-DOC-003 (a field role reads the report: masked columns absent).
Done when: demo step 5 (PDF → phone scans the QR → "Verified") runs on the local stack.

## 2. Slices

Each slice is one PR, tested, CI green, docs swept (ADR-0040 "as built", tracker, hand-off).

| # | Slice | Status |
|---|---|---|
| 1 | PDF engine spike (one day): PDFsharp + MigraDoc 6.2.4 (MIT, licence read from the package) renders the generated 200-entry shift with signature images and an embedded open-licence font in < 10 s; measured in a test; the result goes into ADR-0040 (QuestPDF only with the owner's approval of its licence): [spikes/pdf-engine](../../../spikes/pdf-engine/README.md), 0.6–0.8 s cold, fonts in `src/backend/Modules/Documents/Fonts` | ✅ #260 |
| 2a | The read contracts the report needs, in the modules that own the data: FieldOps `IShiftEntriesOfShift` (a shift's current entry versions on a site: machine, operator, meter kind, start and end values and times, status, flags, envelope, corrector), Verification `IReviewOutcomes` (each record's decision and who decided), Trust `IEnvelopeImages` (the handwritten signature image hash of each envelope, the image itself from the evidence store), Identity `IUserNames.ByIdAsync` (names by user ID); Assets' `IAssetDirectory` already gives machine codes | ✅ #261 |
| 2b | Documents module: the shift report's data from those contracts, masked per the reader's role (`SensitiveExport`, TC-P2-DOC-003), its canonical form (RFC 8785) and hash: `ShiftReportContents`, permission `documents.shift-reports.read`; no field is sensitive today, the test uses a test-only one | ✅ #262 |
| 3a | The PDF renderer: `ShiftReportPdf` (Documents.Infrastructure) renders `ShiftReportContent` with PDFsharp + MigraDoc 6.2.4: header, the reader's table, signature images, footer with the content hash, the verification address (without its token) and a QR (QRCoder's matrix drawn as an 8-bit grey PNG); Noto Sans embedded from the assembly; French or English titles; 200 entries < 10 s (TC-P2-DOC-001 timing) | ✅ #264 |
| 3b | The document envelope and the endpoint: envelope table (schema `documents`, RLS), content and PDF hashes ledgered at issue (`documents.shift_report_issued.v1`), the token (128 random bits) stored hashed, signature images from the evidence store, `GET /documents/shift-reports?siteId&date&shift` returning the PDF (TC-P2-DOC-001): `DocumentEnvelope` (`documents.envelopes`), `ShiftReportIssuing`, `IssueShiftReport` endpoint, header `X-Karry-Envelope`, setting `Documents:VerifyOrigin` | ✅ #265 |
| 3c | Server signature: a Trust contract for signing digests; a Workers job signs the issued envelopes when the signing service answers (as countersigning): `IDigestSigner`, `SignDocuments`, Workers job `document-signing`, `documents.envelope_signed.v1` | ✅ #266 |
| 4 | Public verification API: `POST /verify/{envelopeId}` with the token in the body (anonymous, platform address, rate-limited per address), one "not found" for every miss with equal work (TC-P2-SIG-005), the answer limited by the company's policy; comparing a PDF's hash (TC-P2-DOC-002): `VerifyDocument` at `/api/v1/documents/verify/{envelopeId}`, `DocumentVerification`, global table `documents.verification_keys`; no names (a company setting later) | ✅ #267 |
| 5a | The public page `/verify/{envelopeId}#{token}` in the portal: rendered before and without sign-in (`main.tsx` → `VerifyApp`), the token read from the fragment and posted, "Verified" (type, company, site, shift, hashes, the server's signature or "pending"), "Not found", "Too many checks", and a dropped PDF hashed in the browser ("This PDF is the issued document" / "Not genuine"); five languages | ✅ #269 |
| 5b | The shift report from the portal: download from the board and the review queue (site, date, shift, language): `ShiftReportButton` on each shift card of the board and in the review drawer of a shift entry, shown with `documents.shift-reports.read` | 🟡 in review |
| 6 | Close-out: demo step 5 E2E (PDF → QR → "Verified"), the security review (T-09, T-10, enumeration and timing, the public page's policy), ADR-0040 accepted | ⬜ |
