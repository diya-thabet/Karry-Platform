# P2.11 shift report PDF and public verification: slice plan

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Sub-phases](sub-phases.md#p211--shift-report-pdf--public-verification) · [Tracker](tracker.md)

**In plain words:** a signed shift report anyone can print. Its QR code opens a public page that says whether the
document is genuine, and a PDF changed by one byte is shown as not genuine. Design: [ADR-0040](../../adr/0040-documents-and-public-verification.md).

## 1. Scope

| Story | ACs in P2.11 |
|---|---|
| US-P2-SIG-05 Signed shift report PDF | AC1 (per shift and site: entries with values, Δ, operator, controller, flags, signature images, verification QR), AC2 (document hash in the footer, QR to the verification page), AC3 (200 entries in < 10 s) |
| US-P2-SIG-06 Public verification page | AC1 (type, date, issuing company, status, hash; names only as the company's policy allows), AC2 (rate-limited, no enumeration) |

Tests: TC-P2-DOC-001 (200 entries < 10 s, the QR verifies), TC-P2-SIG-005 (enumeration: random IDs and tokens give
the same "not found" answer and timing; the rate limit hits), TC-P2-DOC-002 (a changed PDF byte → "not genuine"),
TC-P2-DOC-003 (a field role reads the report: masked columns absent).
Done when: demo step 5 (PDF → phone scans the QR → "Verified") runs on the local stack.

## 2. Slices

Each slice is one PR, tested, CI green, docs swept (ADR-0040 "as built", tracker, hand-off).

| # | Slice | Status |
|---|---|---|
| 1 | PDF engine spike (one day): PDFsharp + MigraDoc 6.2.4 (MIT, licence read from the package) renders the generated 200-entry shift with signature images and an embedded open-licence font in < 10 s; measured in a test; the result goes into ADR-0040 (QuestPDF only with the owner's approval of its licence): [spikes/pdf-engine](../../../spikes/pdf-engine/README.md), 0.6–0.8 s cold, fonts in `src/backend/Modules/Documents/Fonts` | 🟡 in review |
| 2 | Documents module: the shift report's data from the other modules' contracts (entries and Δ from FieldOps, decisions and controller from Verification, flags from Integrity, signature strokes from Trust, site and shift from Organization, names from Identity), masked per the reader's role (`SensitiveExport`, TC-P2-DOC-003), its canonical form (RFC 8785) and hash | ⬜ |
| 3 | The PDF and its envelope: rendering (footer with the data hash, QR to `/verify/{envelopeId}#{token}`), the PDF's SHA-256 and the data hash signed by the server key and ledgered (`documents.shift_report_issued.v1`), the token (128 random bits) stored hashed; `GET /documents/shift-reports?siteId&date&shift` (TC-P2-DOC-001) | ⬜ |
| 4 | Public verification API: `POST /verify/{envelopeId}` with the token in the body (anonymous, platform address, rate-limited per address), one "not found" for every miss with equal work (TC-P2-SIG-005), the answer limited by the company's policy; comparing a PDF's hash (TC-P2-DOC-002) | ⬜ |
| 5 | Portal: the shift report from the board and the review queue; the public page `/verify/{envelopeId}#{token}` (no sign-in, the token read from the fragment and posted, a strict page policy), "Verified" / "Not genuine" / "Not found", and checking a dropped PDF in the browser | ⬜ |
| 6 | Close-out: demo step 5 E2E (PDF → QR → "Verified"), the security review (T-09, T-10, enumeration and timing, the public page's policy), ADR-0040 accepted | ⬜ |
