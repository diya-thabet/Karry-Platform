# P2.12a security review of sync and signatures

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Hardening plan](p2.12a-hardening-plan.md) · [Threat model](../../02-architecture/threat-model.md)

**In plain words:** before the pilot, someone tries each attack the Phase 2 plan names against the tablet uploads and
the signed records. Every attack is a test that runs in CI. This page lists the attacks, the tests that hold the line,
and what is still open. One small fix (a forged enrolment key ended in an error on Windows instead of a refusal) and one missing test
(a changed record replayed under an existing command ID).

## 1. Scope

Phase 2 adds field signatures, evidence photos, verification and public document checks on top of the Phase 1 sync.
The review covers the attack list of the [sub-phase card](sub-phases.md#p212--hardening-non-functional-tests-shadow-run--exit-gate-m2)
and the threats it maps to in the [threat model](../../02-architecture/threat-model.md#3-top-threats-stride-mitigations-and-verification).
Each suite listed below was run again on 2026-11-26 against `main` plus this slice, and passed.

## 2. Attacks and the tests that refuse them

| Attack | What the server does | Tests (all in CI) | Threat |
|---|---|---|---|
| **Payload modified after signing** (TC-P2-SIG-002) | The envelope (RFC 8785) binds the record, evidence and handwriting hashes; one changed character fails on the tablet and on the server, and the command is rejected for good (`sync.signature_invalid`) | `SignatureEnvelopesTests` (vectors shared with `@karry/crypto`'s `envelope.test.ts`), `EnvelopeVerificationTests`, `EnvelopeRecorderTests`, `ShiftEntryHandlersTests`, `SyncBatchesTests` | T-03 |
| **Replay with a modified payload, re-signed by the tablet** (new in this slice) | A command ID already stored is a duplicate, whatever its payload or place in the sequence; the stored command is never rewritten. A change is a new command (a correction, ADR-0034) | `SyncBatchesTests.A_stored_command_sent_again_with_another_payload_signed_anew_is_a_duplicate_and_the_first_stays` | T-05 |
| **Replay of a valid batch** (TC-P2-SYNC-001) | Stored once; the same batch fired many times at once is stored once, never a 500 | `SyncBatchesTests` (H-C3), `InboxRulesTests` | T-05 |
| **Forged or stolen enrolment** | Codes are 16 Crockford characters, single use, 15 minutes, kept hashed; a proof by another key, another company's code or a race for one code enrols nothing (or exactly one); every device request is signed, bound to method, path and time, and single use | `DeviceApiTests`, `DeviceTests` | T-02 |
| **Revoked tablet** (TC-P2-SIG-003) | Its requests get `401`; its envelopes are refused even with a valid signature; commands already queued are kept quarantined | `DeviceApiTests`, `EnvelopeRecorderTests`, `SyncBatchesTests` | T-02 |
| **Server key rotation** (TC-P2-SIG-004) | Documents and countersignatures signed by the old key still verify after rotation | `OpenBaoTransitSignerTests`, `CountersignTests`, E2E `field-key-rotation.spec.ts` | T-03 |
| **Pre-signed URL misuse** (TC-P2-SYNC-012) | The URL is good for one key, one size and one checksum for 15 minutes; the key is built from the signed tablet's company and device; other bytes, another checksum header or an expired URL are refused by the store; a blob replaced around the API is rejected for good with a security event | `PresignedChecksumTests`, `SyncBlobsTests` | T-03, T-09 |
| **Separation-of-duties bypass** (TC-P2-VER-003) | A correction beyond the thresholds waits for a second approver who is not the corrector, checked on the server at action time through the office ↔ field account link | `ReviewDecisionsTests` ([ADR-0037 §9](../../adr/0037-verification-engine.md#9-security-review-p28-close-out-2026-11-24)) | T-13 |
| **Public verification page enumeration** (TC-P2-SIG-005) | Every miss is the same `404 documents.not_found`; the 128-bit token is kept hashed and compared in constant time; no person's name or company ID in the answer; anonymous checks past the per-address limit get `429` | `VerifyingTests`, `RateLimitWiringTests`, E2E `shift-report.spec.ts` | T-09, R-16 |
| **Tablet clock set +3 h** (TC-P2-SYNC-008) | The entry is stored with the `CLOCK_SKEW` flag; the tablet signs the clock offset it knew | `ClockSkewTests`, `signShiftEntry.test.ts` | T-04 |

## 3. Findings

| # | Finding | Decision |
|---|---|---|
| S-1 | No test proved that a stored command ID replayed with a different, validly signed payload leaves the first command untouched. The server already behaved correctly (the inbox decides by command ID before the payload). | Test added. |
| S-2 | The per-address limit on anonymous document checks is counted per API instance. | Already residual risk R-16: a shared limit comes with the deployment (P2.12b). |
| S-3 | A document token cannot be revoked yet. | Already residual risk R-16. |
| S-4 | An enrolment whose public key is not a point of P-256 was refused on Linux but threw on Windows: .NET on Windows (CNG) raises `PlatformNotSupportedException`, not `CryptographicException`, so the request would have ended in a 500 instead of `devices.key_invalid`. Found by running `DeviceTests` on the owner's Windows machine; CI and production run Linux, where it was refused. | **Fixed:** the enrolment check and the device request check treat both exceptions as "not a key" (`Device.ProvesKey`, `DeviceAuthentication`). |

Only S-4 needed a code change; it is fixed. Nothing else blocks the pilot.
