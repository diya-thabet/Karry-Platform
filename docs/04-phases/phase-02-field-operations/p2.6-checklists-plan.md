# P2.6 pre-start checklists: slice plan

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Sub-phases](sub-phases.md#p26--pre-start-checklists) · [Tracker](tracker.md)

**In plain words:** before a machine starts, its operator answers the machine's checklist on the tablet; a critical
"not OK" puts the machine on hold until a manager releases it with a reason. Design:
[ADR-0035](../../adr/0035-pre-start-checklists-and-safety-holds.md). P2.5's last item (9b: usability test and demo) is
the owner's and does not block this work.

## 1. Scope

| Story | ACs in P2.6 |
|---|---|
| US-P2-FO-02 Pre-start checklist | AC1 (required or optional per template), AC2 (OK / Not OK / N/A, photo on a critical Not OK), AC3 (critical Not OK → unsafe, start blocked, manager override audited; the notification itself is P2.10) |
| US-P2-FO-03 Template builder | AC1 (per asset type: items, critical, photo, texts in the company's languages), AC2 (versions; a submission keeps its version) |

Tests: TC-P2-FO-004 (critical Not OK → hold, start blocked on the tablet, flagged on the server, event raised),
TC-P2-FO-013 (template changed while a tablet is offline → its submission keeps the version it used), TC-P2-FO-014
(release without the permission → 403; with it → ledgered). Done when: a seeded excavator checklist works offline end
to end, including the override.

## 2. Slices

| # | Slice | Status |
|---|---|---|
| 1 | Templates (FieldOps): each publish is the next frozen version, per asset type, `required`; API with `fieldops.checklists.read`/`manage`; append-only migration with RLS; isolation suite; OpenAPI (TC-P2-FO-013 templates) | ✅ |
| 2 | Portal template builder (Settings → Pre-start checklists): newest version per machine type, builder for the next version (texts per language with the company's first, critical forces a photo, codes made from the text, reorder), versions with their items; checked before sending | ✅ |
| 3 | Submissions and holds (server): command `fieldops.checklist.submit.v1` checked against the version, `fieldops.checklists` and `fieldops.safety_holds` append-only, event `asset_marked_unsafe`, start flagged `ASSET_UNSAFE`; release API with `fieldops.holds.release`, ledgered (TC-P2-FO-004 server, 013, 014) | ✅ |
| 4 | Sync: `checklistTemplates` and `safetyHolds` collections; Dexie v6; shared vectors for the answer rules | ✅ |
| 5 | Tablet checklist step before a start (required or optional), photo on a critical Not OK, sign and enqueue; start blocked on a held machine (TC-P2-FO-004 tablet) | ✅ |
| 6 | Portal holds: list of open holds per site, release with a reason (permission), history | 🟡 in review |
| 7 | Close-out: demo excavator checklist in the seed, browser E2E offline end to end with the override, security review, ADR-0035 accepted, five languages | ⬜ |

Each slice is one PR, tested, CI green, docs swept (ADR-0035 "as built", tracker, hand-off).
