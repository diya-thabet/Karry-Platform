# P2.7 meter events, continuity and integrity flags v1: slice plan

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Sub-phases](sub-phases.md#p27--meter-events-continuity--integrity-flags-v1) · [Tracker](tracker.md)

**In plain words:** the system checks that each shift starts where the last one ended, explains the gaps it can (a
meter replaced, reset or broken) and raises a flag for the ones it cannot; flags are kept, closed when they no longer
hold, never deleted. Design: [ADR-0036](../../adr/0036-integrity-rules-and-flags.md).

## 1. Scope

| Story | ACs in P2.7 |
|---|---|
| US-P2-FO-07 Inter-shift continuity | AC1 (start ≠ last end of the meter, unexplained → flag linked to both entries), AC2 (re-evaluated in shift-time order when a late entry arrives), AC3 (the flag carries both photos; the controller queue itself is P2.8) |
| US-P2-AST-01 Meter replacement / reset | AC1 (replaced: old final, new initial, time, photos, reason; usage stays continuous by an offset), AC2 (reset/rollover the same), AC3 (recorded by an authorised manager, ledgered) |
| US-P2-AST-02 Meter failure | AC1 (manager marks a meter failed; the tablet asks for operating times instead of readings), AC2 (entries `estimated`), AC3 (a repair reading closes the failure) |
| US-P2-INT-01 Integrity flags v1 | AC1 (RULE-FO-01 … 07), AC2 (severity, explanation in five languages, evidence links), AC3 (tenant thresholds and switches; security rules cannot be switched off) |

Tests: TC-P2-FO-007 (night start ≠ day end → flag, both entries linked), TC-P2-FO-008 (late offline entry → re-evaluated
in shift order), TC-P2-FO-009 (meter replaced → no flag, usage continuous), TC-P2-FO-010 (failed meter → `estimated`
until repaired), TC-P2-INT-001 … 007 (one positive and one negative case per rule), a property test (random readings and
events → a flag exactly where an unexplained discontinuity is; CsCheck, the repository's property-test library, shrinking on) and its mutation check. Done
when: the generator's anomalies all come out as the right flags, and only those.

## 2. Slices

Each slice is one PR, tested, CI green, docs swept (ADR-0036 "as built", tracker, hand-off).

| # | Slice | Status |

## 3. Decisions taken here

- **Flags live in a new Integrity module**, raised by the module that owns the facts (FieldOps for shift entries,
  Assets for meter events, Sync for devices) through `Integrity.Contracts`, in the same transaction as the fact.
- **Shift entries keep their own flags per version** (ADR-0034 §6, what the tablet shows); Integrity flags are the
  case-managed view that opens and closes over time.
- **The continuity engine is a pure function** over one meter's segments and events, ordered by shift time; it runs for
  the meter whenever one of its facts changes, and its answer replaces the meter's open RULE-FO-01 flags (new ones
  opened, ones that no longer hold closed with the reason "re-evaluated").
- **A meter event is a manager's decision** recorded in the portal (authenticated, ledgered under their name), with
  photos uploaded as evidence; the tablet does not record meter events in P2.7.
