# P2.9 controller console: slice plan

> [Docs index](../../README.md) › [04-phases](../README.md) › [Phase 2 plan](plan.md) · [Sub-phases](sub-phases.md#p29--controller-console) · [Tracker](tracker.md)

**In plain words:** the controller's screen. A queue in risk order, the meter photos side by side, the keyboard
instead of the mouse, and a board of the current shift. Design: [ADR-0038](../../adr/0038-controller-console.md);
the decisions underneath are P2.8's ([ADR-0037](../../adr/0037-verification-engine.md)).

## 1. Scope

| Story | ACs in P2.9 |
|---|---|
| US-P2-VER-01 Review queue | AC1 (the caller's sites, risk first then age), AC2 (filters: site, shift date, asset, operator, flag), AC3 (key values, Δ, flags, thumbnails), AC4 (a new synced entry within 10 s) |
| US-P2-VER-07 Fast review UX | AC1 (A/R/C/J/K, swipe on tablets), AC2 (zoom, previous and current photos side by side), AC3 (50 unflagged entries in < 5 min, usability protocol) |
| US-P2-VER-08 Shift board | AC1 (per shift: planned, started, ended, missing end, pending, flags), AC2 ("missing end" 1 h after the shift ended) |
| From P2.8 | Overdue first (`?overdue=true`), the continuity-gap settlement dialog, the R-15 warning (a site reviewer without a linked field account while a field account of the same name exists) |

Tests: TC-P2-VER-010 (a new synced entry in the queue within 10 s, browser E2E), TC-P2-VER-011 (shortcuts do
nothing while typing in the correction dialog), axe on the queue, the detail and every dialog.
Done when: demo step 3 runs (the queue shows the continuity exception with the photos side by side).

## 2. Slices

Each slice is one PR, tested, CI green, docs swept (ADR-0038 "as built", tracker, hand-off).

| # | Slice | Status |
|---|---|---|
| 1 | Queue API: `sort=risk` (overdue, flagged, oldest) with a stable cursor, filters (asset, operator, flag, covered date), `ETag`/304: `risk` column kept by the domain (backfilled), cursor placed by the cursor item's current risk, `producedBy`, `flag`, `coveredFrom`/`coveredBefore` | ✅ #238 |
| 2 | Entry photos: `IEvidenceStore` read, `GET /fieldops/entries/{id}/photos/{sha256}` (only a photo the entry names, site scope, image headers); the previous segment on the meter in the entry detail: key from the first version naming the photo with a tablet, `previousOnMeter` when the caller sees its site | ✅ #239 |
| 3 | Portal queue (Review › Queue): rows with values, Δ, flags in words, thumbnails, overdue and escalated chips, filters, polling every 5 s with `If-None-Match`: sidebar section Review (`/review`), entries of the page in one `GET /fieldops/entries?ids=` (up to 200), site, flag and overdue filters | ✅ #240 |
| 4 | Item detail: photos side by side with zoom, flags explained, verification badge, versions; approve, reject (reason code and comment), correct (before → after), second approval, step-up and 409 handling: a panel from each queue row, previous end on the meter beside this start and end, only changed values sent | 🟡 in review |
| 5 | Keyboard and speed: A/R/C/J/K, `?` overlay, never inside fields or dialogs (TC-P2-VER-011); bulk approve of unflagged items; swipe on tablets | ⬜ |
| 6 | Continuity gaps: settle dialog (reason, what happened), approve or decline another person's, RULE-FO-11 shown; R-15 warning on the queue | ⬜ |
| 7 | Shift board and RULE-FO-08 (missing end 1 h after the shift, Workers job, closed when the end arrives) | ⬜ |
| 8 | Close-out: browser E2E TC-P2-VER-010 and demo step 3, usability protocol (50 entries < 5 min, proxy), axe, security review, ADR-0038 accepted | ⬜ |
