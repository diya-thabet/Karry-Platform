# ADR-0026 — Asset registry with a type catalogue in code, append-only site and meter history, random label tokens

## Context

Every later operation (shifts, fuel, maintenance, costs) is attributed to a machine, so the register is the first
thing a quarry fills in. The stories leave five questions open:

1. **Who owns the machine types.** AC1 lists seeded types; AC2 gives each one default meters and component templates
   that Phase 4 (maintenance) uses.
2. **Where an asset is.** An asset belongs to a site (the plan limit is per site), but it moves, and its history must
   follow it without being copied (bounded contexts §9.4).
3. **How a QR label identifies an asset.** The label is printed and glued on a machine. Anyone can photograph it, and
   it must not reveal or guess other assets, nor work in another company (TC-P1-AST-001).
4. **What "append-only meter history" means** in P1, when field readings only arrive in Phase 2.
5. **How search works** on codes, plates, makes and models (AC4).

## Decision

1. **The type catalogue is code in the `Assets` domain, the same for every company.**
   - Each type has a code (`excavator`, `wheel-loader`, `haul-truck`, `dozer`, `grader`, `drill-rig`, `crusher-jaw`,
     `crusher-cone`, `crusher-impact`, `crusher-vsi`, `screen`, `washer`, `conveyor`, `generator`, `fuel-bowser`,
     `light-vehicle`, `other`), its default meters (`hours`, `km`, both or none) and its component templates.
   - The apps translate the type names; `GET /api/v1/assets/types` lists the catalogue.
   - The owner reviews the defaults (D-03). Company-specific types wait for a customer who needs them.
2. **One asset, one identity, one current site; the site history is append-only** (§9.4).
   - `assets.assets` holds the current state: code (unique per company, fixed), name, type, make, model, serial/VIN,
     plate, year, acquisition date, current site and status (`active`, `in-repair`, `idle`, `disposed`).
   - `assets.site_assignments` gets one row per arrival at a site (`asset`, `site`, `from`). A row is never updated or
     deleted: a trigger refuses it and `karry_app` has no `UPDATE`/`DELETE` on the table. A stay ends where the next
     one starts.
   - Permissions are site-scoped: `assets.registry.read` (every role, on its sites) and `assets.registry.manage`
     (Tenant Admin, Site Manager, Maintenance Planner, on their sites). Moving an asset needs `manage` on both sites.
     An asset outside the caller's sites does not exist for them (404).
3. **The asset-count meter counts assets that are not disposed.** Registering an asset, or bringing a disposed one
   back, goes through the plan's soft limit (`assets` metric: assets per site × sites + extra assets, ADR-0023).
4. **A QR label carries a random token, not the asset ID and not a signature.**
   - Each asset has a 128-bit random label token (base32), unique and stored with the asset. The label encodes
     `KRY1:<token>`. `GET /api/v1/assets/labels/{token}` resolves it inside the caller's company (RLS), so a label of
     company A scanned in company B is "not found".
   - **Why not a signed reference:** resolving needs the company's register anyway, so a signature adds a key to
     rotate without adding a check. A random token cannot be guessed or enumerated, does not reveal the ID, and can be
     verified offline against the register the field app downloads.
   - Reissuing a label replaces the token, so a lost or stolen label stops working.
   - The printable sheet is a PDF generated by the API: A4, 3 × 8 labels of 70 × 37 mm. QRCoder (MIT) draws the
     matrix, and a small PDF writer of our own draws it with the standard Helvetica font, so no font files are needed.
5. **Meters and their readings.**
   - An asset has 0..n meters (`hours`, `km`) with an initial reading, an installation date and a status (`ok`,
     `failed`, `replaced`). A new asset gets its type's default meters unless the request lists its own.
   - Readings are in `assets.meter_readings`, append-only the same way as site assignments (trigger plus `REVOKE`).
     Every reading is in the company's ledger. A reading below the previous one, or in the future, is refused.
   - Replacing a meter (a new meter with an offset, `MeterReplaced`) is Phase 2. The `offset` column exists now and
     stays 0.
6. **Search uses trigram matching.** A generated, lower-cased `search_text` column (code, name, make, model, serial,
   plate) has a `pg_trgm` GIN index, so a fragment of a plate or a serial matches. Filters: site, type, status
   (disposed assets only when asked). Paging is cursor-based on the code, at most 200 per page.
   `pg_trgm` is created by the environment (`deploy/database/extensions.sql`), like PostGIS.
7. **Photos are in object storage**, one current photo per asset, under a key with the company and the asset; the API
   streams them after the same checks as the asset itself.
   - A shared `IObjectStore` in BuildingBlocks (S3 API; SeaweedFS locally) is configured by the `Storage` section and
     writes keys `tenants/{tenant}/{module}/...`, so every later module (documents, attachments) uses the same bucket
     layout. Without a bucket the photo routes answer 422 `assets.photos_unavailable`.
   - The asset keeps the photo's SHA-256, type and size; the key contains the hash, so a replaced photo never overwrites
     the one an open page still shows, and the old object is deleted after the asset is saved.
   - Only JPEG, PNG and WebP up to 5 MB, recognized from their first bytes rather than the declared type (an SVG with
     script is refused). Served with `nosniff` and `default-src 'none'`.

## Options considered

- **Types as tenant data seeded at provisioning.** Rejected for now: nobody has asked to add types, and seeding
  copies would need a migration for every catalogue change. A tenant table can be added later without changing assets.
- **Signed label reference (HMAC of company and asset).** Rejected for the reasons in decision 4.
- **The asset ID in the label.** Rejected: an ID reveals creation time (UUIDv7) and cannot be revoked.
- **Full-text search.** Rejected: the fields are codes and brand names, not prose; stemming does not help and partial
  matches would not work.
- **A third-party PDF library.** Rejected: the sheet is rectangles and short text; libraries need fonts in the
  container or carry commercial licences.

## Consequences

- ✅ A label is useless outside its company and after a reissue. Nothing on it can be used to find another asset.
- ✅ Site and meter history cannot be changed, even by a bug in the API (TC-P1-AST-002).
- ⚠ An existing local database volume needs `CREATE EXTENSION pg_trgm` once, by an administrator (new volumes get it
  from `extensions.sql`).
- ⚠ The seeded types and their default meters are drafts until the owner reviews them (D-03).
