# Tables WITHOUT the standard tenant row-level security (US-P1-TEN-02 AC5). Every other table in a Karry schema must
# have `tenant_id uuid NOT NULL`, RLS ENABLE + FORCE and the `tenant_isolation` policy (EnableTenantRls).
# Checked against the migrated database by the migration linter (TC-P1-TEN-004); a stale entry also fails.
#
# Format: schema.table | kind | reason        (schema `*` = every module schema)
#   global         no tenant_id, no RLS: platform or reference data that holds no tenant's business data
#   platform-rows  nullable tenant_id + RLS that also admits no-tenant rows (EnableTenantRls allowPlatformRows)
#
# Adding a line is a security decision: say why the table cannot leak one tenant's data to another.

*.outbox_messages      | global        | Dispatcher infrastructure: read only by the worker, never exposed by an API; each row carries tenant_id and subscribers run in that tenant
*.processed_messages   | global        | Dispatcher de-duplication (message id + handler name), no business data
tenancy.tenants        | global        | Tenant catalog: slug, name and company settings (no personal data), needed before a tenant is known (address check, login branding, provisioning); settings changes are ledgered in the tenant's chain
tenancy.tenant_logos   | global        | Company logos, public by design (sign-in page, threat model R-07); changes are ledgered (fingerprint) in the tenant's chain
platform.idempotency_records | platform-rows | Stored responses of operator requests have no tenant; tenant rows are isolated by RLS
identity.import_cursors | global        | Importer positions (e.g. time of the last Keycloak event read): one row per source, no tenant data
billing.plans          | global        | Plan catalogue (features, limits, price book): Karry's own packaging, the same for every tenant, no tenant data
flags.platform_flags   | global        | Platform-wide flag values of this environment (kill switches): Karry's own rollout settings, no tenant data
flags.platform_flag_changes | global   | Append-only history of platform-wide flag changes (who, before, after, when); no tenant data
audit.server_keys      | global        | Public keys of the server's signing key versions (kid, SPKI PEM): public by design so anyone can verify a countersignature; no tenant data; append-only (ADR-0033 §3)
